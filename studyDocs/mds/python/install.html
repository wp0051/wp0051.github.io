Python 安装与环境管理

一、安装 Python

  • 浏览器访问 https://www.python.org/downloads/ 下载
    • 安装时勾选 Add python.exe to PATH（把 python 加入环境变量）
      • 只装一个版本：建议勾选，终端可直接用 python
      • 打算用 py 管理多个版本：可以不勾——py launcher 装在系统目录、不依赖 PATH；不勾选只是为了避免 python 命令固定指向某一个版本，多版本时统一用 py 启动即可
    • 验证安装：python --version；macOS 自带历史遗留的 Python 2，需用 python3 --version

二、为什么需要环境管理：先分清两个问题

Python 的 pip 不像 Node 的 npm install axios 装到当前目录 node_modules，而是装进当前解释器的全局/用户级 site-packages，多个项目共用一套包就会互相污染。这实际包含两个正交问题：

  1. 多版本解释器管理：项目 A 要 3.11、项目 B 要 3.14，如何共存与切换
  2. 项目依赖隔离：每个项目拥有独立的一套包，互不污染、版本可复现

两条解决路线：

  • 路线一 Conda：一个工具同时解决 1 和 2，还能装 C 库/二进制程序，AI 与数据开发常用
  • 路线二 组合式：py(Windows) / pyenv(macOS/Linux) 解决问题 1；venv 或 Poetry 解决问题 2

三、路线一：Conda（版本 + 依赖一体化）

Conda 不是专门为管理 Python 版本设计的，它通过创建多个虚拟环境（文件夹），每个环境里装一套专属的包；conda activate 把该文件夹插到 PATH 最前面，当前终端优先使用环境内的版本，conda deactivate 或关闭终端即恢复，不改动系统全局环境变量。

一个 conda 环境中存放着：

  • 使用 conda install 安装的各类包（Python、C 库、nodejs、jdk、二进制程序等）
  • 环境激活状态下，用该环境内部 pip 安装的 Python 包

常见疑问：

  • node 若是 conda 装的，npm -g 装的全局包在删除环境时会一并删除，但 conda 不认识它们，导出 yml 也不会包含 npm 依赖
  • conda 不直接认识 pip 包，但导出环境时会调用环境内的 pip 查询，pip 包会被写入 yml 的 pip 段落

Conda 有两个发行版：Anaconda（预装大量科学计算包）和 Miniconda（纯净版，按需安装）。

# 下载 Miniconda：https://docs.conda.io/en/latest/miniconda.html

# 创建名为 py311 的环境并指定 Python 版本（conda 用单等号 = 指定版本）
conda create -n py311 python=3.11
# defaults 频道没有的包（如 langchain）用 -c 指定 conda-forge 频道
conda create -n py311 python=3.11 -c conda-forge langchain=1.2

conda activate py311              # 激活，提示符前出现 (py311)
conda deactivate                  # 退出当前环境
conda env list                    # 查看所有环境（* 为当前环境）
conda list                        # 查看当前环境已安装的包

conda install langchain           # 在当前激活环境装包
conda install -n py311 langchain  # 给指定环境装包（无需先激活）
conda update langchain            # 更新指定包
conda update --all                # 更新环境内全部包

# 重命名（conda 4.14+；重命名前必须先 deactivate 该环境）
conda rename -n py311 py3110
conda env remove -n py311         # 删除环境

# 导出完整快照（含精确版本和 build，适合同平台复现）
conda env export -n py311 -f py311.yml
# 跨平台复现推荐：只导出手动安装的包，不带平台相关 build
conda env export -n py311 --from-history -f py311.yml
# 用配置文件创建环境（-n 会覆盖 yml 内的 name 字段；文件后缀只认 yml/yaml）
conda env create -n py311_copy -f py311.yml

最佳实践：优先 conda install；conda 频道没有的包再用环境内 pip，且 pip 尽量集中在最后安装——conda 后续解析时无法感知 pip 的改动，反复混装容易破坏依赖。

四、路线二：py/pyenv 管版本 + 虚拟环境管依赖

4.1 多版本解释器管理

py（Windows，Python 3.3 起官方自带）

py                       # 启动默认版本（已安装的最高稳定版）
py --version

# 列出已安装版本（短写 -0）；加 paths 同时显示安装路径（短写 -0p）
py --list
py --list-paths

# 按版本启动：-大版本 或 -大版本.小版本
py -3                    # 最新的 3.x
py -3.11                 # 最新的 3.11.x
py -3.11 script.py       # 用指定版本运行脚本
py -3.11 -m pip install requests   # 用指定版本的 pip 装包
py -3.11 -m venv .venv             # 用指定版本创建虚拟环境

默认版本选择优先级：命令行 -x.y 指定 > 环境变量 PY_PYTHON（如 PY_PYTHON=3.11）> py.ini 的 [defaults] 配置 > 已安装的最高版本。

版本变化：Python 3.14 起经典 py.exe launcher 被标记弃用（计划 3.16 起不再随安装器提供），官方改为 Python Install Manager，新写法为 py list、py -V:3.14。已安装的 3.13 及更早版本仍使用上面的经典命令，过渡期两套共存。

pyenv（macOS / Linux）

# 安装：macOS 推荐 Homebrew
brew install pyenv
# 通用官方脚本（克隆到 ~/.pyenv）
curl https://pyenv.run | bash

安装后配置 shell（以 zsh 为例写入 ~/.zshrc，bash 写入 ~/.bashrc），再 source ~/.zshrc：

export PYENV_ROOT="$HOME/.pyenv"
[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init -)"

pyenv 是编译安装 Python，首次使用需先装构建依赖（Ubuntu/Debian）：

sudo apt-get update && sudo apt-get install -y make build-essential \
  libssl-dev zlib1g-dev libbz2-dev libreadline-dev libsqlite3-dev \
  curl git libncursesw5-dev xz-utils tk-dev libxml2-dev \
  libxmlsec1-dev libffi-dev liblzma-dev

Windows 不支持原生 pyenv：官方方案是上面的 py launcher，第三方替代为 pyenv-win。

pyenv install --list | grep 3.11    # 查看可安装版本（列表很长，用 grep 过滤）
pyenv install 3.11.9                # 编译安装到 ~/.pyenv/versions/
pyenv uninstall 3.11.9              # 卸载版本

pyenv versions                      # 已安装版本列表，* 为当前生效版本
pyenv version                       # 当前生效版本及设置来源
pyenv which python                  # 当前 python 的真实路径

# 三个层级切换，优先级：shell > local > global
pyenv global 3.11.9                 # 全局默认（写入 ~/.pyenv/version）
pyenv local 3.11.9                  # 当前项目：生成 .python-version，进入目录自动切换
pyenv shell 3.11.9                  # 仅当前终端（设置 PYENV_VERSION 环境变量）
pyenv local --unset                 # 取消项目级设置（shell 同理）
pyenv global system                 # 恢复使用系统 Python

pyenv rehash                        # 安装带可执行命令的包后，刷新 shims 索引
pyenv exec python app.py            # 不切换当前版本，临时指定版本执行

工作原理：pyenv init 把 shims 目录插到 PATH 最前面，拦截 python/pip 等命令，再按 shell（PYENV_VERSION）→ local（逐级向上找 .python-version）→ global（~/.pyenv/version）→ system 的顺序决定用哪个解释器，全程不改系统 Python、不需要 sudo。

4.2 项目依赖隔离：虚拟环境

venv 是标准库提供的"环境本体"；Poetry 是在虚拟环境之上再做依赖解析、版本锁定和项目管理。二者是同一层面的两种用法，不是要一起装的两个东西。

venv（标准库，无需安装）

# 用指定版本创建虚拟环境
py -3.11 -m venv .venv              # Windows：py 指定版本

python -m venv .venv                # 不指定版本：用 PATH 中优先级最高的 python

# 激活（激活后提示符前出现 (.venv)，which python 指向项目内）
.venv\Scripts\activate.bat          # Windows CMD
.venv\Scripts\Activate.ps1          # Windows PowerShell
source .venv/bin/activate           # macOS / Linux
# PowerShell 若因执行策略无法激活：Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

pip list                            # 查看已安装的包
pip install langchain               # 安装/卸载（激活后包装进 .venv，不污染全局）
pip uninstall langchain
pip freeze > requirements.txt       # 导出当前环境全部包及精确版本
pip install -r requirements.txt     # 按清单复现环境
deactivate                          # 退出虚拟环境（三端通用）

Poetry 管理依赖

pip + requirements.txt 与 Poetry 对比

  • 依赖冲突检测
    • pip install 逐个安装，冲突是后置发现的，报错不明确
    • Poetry 安装前先完整解析整棵依赖树，算出一套互相兼容的版本再统一安装，冲突时明确指出矛盾双方：
    Because my-app depends on both requests (>=2.0) and lib-x (requests<2.0), version solving failed.
  • 依赖锁定
    • requirements.txt 靠手动 pip freeze 更新，导出的是"当前环境快照"，包含所有临时/废弃包，分不清直接依赖与传递依赖
    • poetry.lock 在 poetry install/add 时自动维护：直接依赖写在 pyproject.toml，完整依赖树锁在 poetry.lock，职责分离
  • 虚拟环境管理
    • pip + venv 需手动建环境、手动激活、手动维护 requirements.txt
    • Poetry 自动检测/创建虚拟环境，poetry run 无需激活即可运行；项目越复杂、协作人数越多优势越明显

安装 Poetry

# macOS / Linux / WSL
curl -sSL https://install.python-poetry.org | python3 -
# Windows (PowerShell)
(Invoke-WebRequest -Uri https://install.python-poetry.org -UseBasicParsing).Content | py -
# 验证
poetry --version

两种创建项目的方式

# 方式一：poetry new —— 从零生成标准目录骨架
poetry new my-project
# my-project/
# ├── pyproject.toml     # 项目配置
# ├── README.md
# ├── my_project/        # 源码目录
# │   └── __init__.py
# └── tests/             # 测试目录
#     └── __init__.py

# 方式二：poetry init —— 在已有目录交互式生成 pyproject.toml（不建骨架、不装依赖）
cd my-project
poetry init
poetry init --python "^3.11"   # 直接声明 Python 版本约束

常用命令

# 版本约束：^3.11 表示 >=3.11.0, <4.0.0；"3.11.0"/==3.11.0 表示锁死唯一版本
poetry install                     # 按 pyproject.toml/lock 建环境并装依赖；无 lock 时解析生成
poetry add langchain               # 添加依赖（自动更新 pyproject.toml 与 poetry.lock）
poetry add pytest --group dev      # 添加到开发依赖组
poetry remove langchain            # 移除依赖
poetry run python app.py           # 无需激活，直接用项目环境运行
poetry run pytest

# 进入激活环境：Poetry 2.0 起 poetry shell 移到 poetry-plugin-shell 插件
# 2.0 内置 poetry env activate 只"打印"激活命令，需交给 shell 执行：
eval $(poetry env activate)               # bash / zsh
Invoke-Expression (poetry env activate)   # PowerShell

poetry env use 3.11                # 指定项目解释器（Windows 无 pyenv 时尤其有用）
poetry env use /full/path/to/python
poetry env info                    # 查看当前环境信息（--path 只看路径）
poetry env list                    # 列出项目关联的所有环境
poetry env remove --all            # 删除项目环境

poetry update                      # 所有依赖更新到约束内最新兼容版本
poetry update langchain            # 只更新指定包
poetry show --outdated             # 查看哪些包有新版本

常用配置与配合：

# 默认虚拟环境建在全局缓存目录；设为 true 后建在项目内 .venv，IDE 可自动识别
poetry config virtualenvs.in-project true
# 与 pyenv 配合：先切版本再安装，Poetry 会自动用当前 python 建环境
pyenv local 3.11.9 && poetry install

项目配置文件 pyproject.toml

[tool.poetry]
name = "my-project"
version = "0.1.0"
description = "项目描述"
authors = ["Your Name <you@example.com>"]

[tool.poetry.dependencies]
python = "^3.11"
langchain = "^0.1.0"

[tool.poetry.group.dev.dependencies]
pytest = "^8.0"
black = "^24.0"
